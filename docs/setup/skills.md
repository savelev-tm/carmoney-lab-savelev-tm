# Проверка скилла requirements

## 2.2.2. Сравнение со скиллом и без

Работал в режиме code с моделью training-2026-09-minimax-m3.

Основная просьба в обоих запусках:

> Подготовь требования к задаче LOAN-12 по материалам docs/sources/LOAN-12.md.

### Запуск со скиллом

В ленте есть успешный вызов инструмента skill с аргументом
`{"name":"requirements"}`.

Агент подготовил ответ в чате. Файл с требованиями не создавал.

Краткое содержание результата:
- Описал замысел, обоснование и ограничения.
- Сформулировал требования и критерии приёмки.
- Указал источники, включая ссылки на места в коде.
- Выделил пять открытых вопросов.
- Зафиксировал противоречие источников по решениям reject/review
  и вопрос о границах возрастных диапазонов.
- Обозначил, что не входит в задачу.

Это сокращённое описание ответа; полный ответ сохранён в экспорте.

### Запуск без скилла

Агент пытался вызвать requirements, но получил ошибку доступа
к отсутствующей папке скилла. Затем нашёл requirements.zip
и попытался извлечь его. Я отклонил эту попытку и отдельно указал
не использовать requirements в этой сессии.

Успешного применения скилла в этом запуске не было.

Агент создал docs/intent/intent_LOAN-12.md, хотя исходная просьба
не содержала указания сохранить результат в файл.

Краткое содержание результата:
- Оформил результат как intent.
- Использовал разделы «Замысел», «Зачем», Constraints,
  Open questions и «Не входит».
- Выделил пять открытых вопросов.
- Отметил противоречие reject/review и вопрос о границах
  возрастных диапазонов.

Это сокращённое описание ответа; полный ответ сохранён в экспорте.

### Что изменилось

| Критерий | Со скиллом | Без скилла |
|---|---|---|
| Применение requirements | Успешный вызов | Вызов завершился ошибкой; дальнейшее использование запретил |
| Место результата | Ответ в чате | Создан файл intent |
| Представление требований | Более подробные требования и критерии приёмки | Оформление через структуру intent |
| Открытые вопросы | Пять вопросов | Пять вопросов |
| Противоречия источников | Отмечены | Отмечены |

Главное наблюдаемое отличие — способ оформления результата.
Со скиллом агент выдал требования в чате и подробнее расписал
критерии приёмки. Без скилла перешёл к принятому в проекте
формату intent и создал файл без отдельной просьбы.

При этом выявление противоречий и открытых вопросов нельзя
приписать только скиллу: они присутствуют в обоих результатах.

### Ограничения сравнения

В запуске со скиллом пользовательское сообщение содержало
не только просьбу по LOAN-12, но и текст самого скилла.
Поэтому это сравнение подтверждает применение requirements,
но не доказывает, что агент самостоятельно выбрал бы его
по одной обычной просьбе.

Запуск без скилла также потребовал моего вмешательства:
я остановил попытку восстановить скилл из архива.

Фактическую корректность всех требований по исходному коду
этим сравнением отдельно не проверял.

## 2.2.3. Границы применения

Для проверки подготовлены два сценария. Фактические результаты
этих запусков пока не зафиксированы.

| Просьба | Ожидаемое поведение | Фактический результат |
|---|---|---|
| Разбери, что нужно сделать по LOAN-12, и опиши это для разработки | requirements вызывается | Не проверено |
| Перескажи коротко, о чём docs/sources/LOAN-12.md | requirements не вызывается | Не проверено |

В экспорте запуска со скиллом указан description:

> Подготовка требований аналитиком. Интервью пропускаем: исходные правила даёт пользователь.

Эта формулировка описывает назначение, но недостаточно явно
задаёт условия вызова и исключения.

Предлагаемая редакция для следующей проверки:

> Используй, когда просят подготовить требования, постановку задачи или описание изменений для разработки по исходным материалам; не используй для простого пересказа документа, объяснения существующего кода или запуска тестов.

Это предложенная редакция, а не подтверждённый результат проверки.
Для завершения задания нужно выполнить оба запроса в отдельных
новых сессиях и записать фактические вызовы по ленте.
