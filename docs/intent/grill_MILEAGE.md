от которых зависит реализация. До вопросов выполнена сверка с

## Вопросы и ответы (в исходном порядке)

### Вопрос 1 — приоритет с `reject`

Заявка с LTV > 85 (сегодня `reject`) и пробегом 400 001 км — каким должно
быть итоговое решение?

- Вариант А: `review` — буквальное прочтение «иначе решение review»:
  правило понижает любой исход, включая отказ (смягчение отказа для авто
  с большим пробегом).
- Вариант Б: `reject` сохраняется — правило ограничивает только `approve`
  (понижает approve → review, но не трогает отказ). Консервативное прочтение.

Оговорка интервьюера: по этому вопросу у AGENTS.md жёсткое правило — без
решения риск-менеджмента логику `DecisionEngine` не менять.

**Ответ: Б.** `reject` сохраняется; правило ограничивает только `approve`
(понижает approve → review, review и reject не трогает).

### Вопрос 2 — пустая строка в поле `mileage`

Сейчас `mileage: ""` молча превращается в 0 км и заявка проходит проверку
пробега. Считать ли пустую строку ошибкой валидации (HTTP 422)?

- Вариант А: оставить как есть — пустая строка = 0 км, поведение
  не меняется (вне scope).
- Вариант Б: пустая строка → 422 — изменение поведения валидатора,
  нужно как отдельное требование.

**Ответ: Б.** Пустая строка в `mileage` — ошибка валидации, HTTP 422.
Оговорка интервьюера (зафиксирована до ответа): это расширяет scope —
правка `ApplicationValidator`, которая в исходном плане была вне задачи.

### Вопрос 3 — причина review в ответе API

Сейчас ответ содержит только `decision`, и по `review` нельзя понять, что
сработало — LTV или пробег. Добавить в ответ признак причины (например,
`reason: high_mileage`) для ручного разбора или оставить форму ответа без
изменений (вне scope)?

**Ответ: без изменений.** Форма ответа API не меняется, признак причины
review не добавляется.

## Факты, не спрашивавшиеся из-за сверки с документами

Эти пункты видны из `docs/setup/code_map.md` и `docs/plan/plan_MILEAGE.md`,
поэтому вопросы по ним не задавались:

- Граница 400 000 включительно («не больше»): 400 000 проходит,
  правило срабатывает с 400 001.
- Пробег `null` / ключ отсутствует: текущая валидация уже даёт 422
  «Пробег от 0 до 500000 км», поведение сохраняется.
- Сочетание с LTV в approve/review-зоне: правило понижает approve до
  review, review остаётся review.
