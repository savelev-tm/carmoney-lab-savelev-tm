# spec_MILEAGE — проверка пробега в решении по заявке

Основа: `docs/intent/intent_MILEAGE.md`. Ничего сверх intent не добавлено.

## Входит / не входит

### Входит

- Проверка пробега в расчёте решения: пробег больше 400 000 км понижает
  `approve` до `review`. Исходы `review` и `reject` не меняются.
- Пустая строка в поле `mileage` — ошибка валидации HTTP 422 (сегодня код
  молча превращает её в 0 км — изменение согласовано в интервью).

### Не входит

- Форма ответа API и признак причины review («из-за пробега») — не
  добавляется (интервью, вопрос 3: «без изменений»).
- Изменение верхней границы валидации 500 000 км, текста ошибки диапазона
  пробега и текстов других ошибок 422.
- Пересчёт уже сохранённых заявок.
- Исправление расхождения докблока и кода `DecisionEngine` при LTV ровно
  60.0 (`<` vs `<=`).
- Изменение порогов LTV: approve < 60.0, review до 85.0 включительно,
  reject выше 85.0 (`backend/config/rules.php`).

## Требования и критерии приёмки

Во всех сценариях остальные поля заявки корректны, LTV соответствует
проверяемому случаю. Валидность самого пробега определяется конкретным AC.
Правило решения по пробегу применяется только после успешной валидации заявки.

### REQ-MILEAGE-01 — порог пробега

Пробег не больше 400 000 км включительно; правило срабатывает с 400 001 км.
Решение понижается с `approve` до `review`. При LTV > 85 решение остаётся
`reject`, даже если пробег выше границы.

Источник: формулировка задачи в интервью («пробег авто не больше 400 000 км,
иначе решение review»); «reject сохраняется — правило ограничивает только
approve» — интервью, вопрос 1, вариант Б.

- AC-MILEAGE-01: заявка с пробегом 399 999 км и LTV, дающим `approve`
  (LTV < 60.0), получает решение `approve`.
- AC-MILEAGE-02: заявка с пробегом 400 000 км и LTV, дающим `approve`,
  получает решение `approve` (граница включительна).
- AC-MILEAGE-03: заявка с пробегом 400 001 км и LTV, дающим `approve`,
  получает решение `review`; `approved_limit` = 0.
- AC-MILEAGE-04: заявка с пробегом в диапазоне 400 000 < mileage ≤ 500 000
  и LTV > 85.0 получает решение `reject` (правило ограничивает только
  `approve`).
- AC-MILEAGE-05: заявка с пробегом в диапазоне 400 000 < mileage ≤ 500 000
  и LTV в диапазоне review (60.0–85.0 включительно) получает решение
  `review`, без изменений относительно текущего поведения.
- AC-MILEAGE-09: заявка с пробегом ровно 500 000 км (проходит валидацию —
  верхняя граница 500 000 км включительна) и LTV, дающим `approve`,
  получает решение `review`; `approved_limit` = 0. Источник: сохранение
  существующей верхней границы валидации 500 000 км
  (`backend/config/rules.php`) плюс согласованное правило пробега
  (интервью: «пробег авто не больше 400 000 км, иначе решение review»).

Источник чисел в AC: границы 399 999 / 400 000 / 400 001 — из формулировки
задачи (порог 400 000 км включительно); диапазон 400 000 < mileage ≤ 500 000
и граница 500 000 — из сохранения верхней границы валидации
(`backend/config/rules.php`), чтобы не противоречить AC-MILEAGE-08; LTV-пороги
60.0 / 85.0 и `approved_limit` = 0 при review — существующее поведение
(`backend/config/rules.php`, `backend/src/Domain/DecisionEngine.php`,
`backend/src/Domain/AssessmentService.php`).

### REQ-MILEAGE-02 — пустая строка пробега

Пустая строка в поле `mileage` — ошибка валидации, HTTP 422 (сегодня код
молча превращает её в 0 км).

Источник: интервью, вопрос 2, вариант Б («пустая строка → 422»).

- AC-MILEAGE-06: заявка с `mileage: ""` получает HTTP 422 и не доходит до
  расчёта решения.

Текст ошибки 422 — см. Open questions; точный текст не зафиксирован.

### REQ-MILEAGE-03 — существующая валидация пробега сохраняется

Пробег `null` или отсутствие ключа `mileage` — HTTP 422 «Пробег от 0 до
500000 км». Верхняя граница валидации — 500 000 км, не меняется.

Источник: существующее поведение кода, не новое требование
(`backend/src/Domain/ApplicationValidator.php`,
`backend/config/rules.php`).

- AC-MILEAGE-07: заявка без поля `mileage` (или `null`) получает HTTP 422
  «Пробег от 0 до 500000 км».
- AC-MILEAGE-08: заявка с пробегом 500 001 км получает HTTP 422 (значение
  вне зоны действия правила REQ-MILEAGE-01).
